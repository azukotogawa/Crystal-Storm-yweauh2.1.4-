# cs-debug-view-toggles

## What landed

Debug views, all off until a debug build has `CRYSTALSTORM_DEV_VIEWS=1`:

- F8 dev menu
- F13 chunk borders (loaded chunks inside a 2-chunk radius, line mesh only while on)
- F14 crystal sim frontier (`CrystalManager.get_depth_cells_in_rect`, 48×48 around the player, cap 180 marks)
- F15 collision (5×5 `walkable_height_at` samples)
- F16 perf overlay (FPS, frame ms, hottest profiler section; no scene walk)

Gate: `0.2.8/helpers/debug_view_gate.gd`. A release export (`OS.is_debug_build()` false, or the `release` feature) ignores the env var. The layer then keeps input off, builds no menu, and builds no mesh. `main.gd` mounts `DebugViewLayer` next to the other dev tools. With the flag unset it does not process and does not draw.

## Render cost

Default play path (flag unset, which is the player default): no `ImmediateMesh`, no perf label, `set_process(false)`, `set_process_unhandled_input(false)`. Terrain shading, ramps, and the medium preset were not edited.
