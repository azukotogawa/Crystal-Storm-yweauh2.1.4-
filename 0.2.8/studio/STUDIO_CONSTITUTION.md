# Crystal Storm Studio Constitution

Version: 1.0

---

# Purpose

Crystal Storm Studio exists to create a living world that rewards curiosity, creativity, and exploration.

The project is developed through collaboration between human vision and autonomous AI engineering.

Humans define purpose.

AI defines implementation.

The repository is the institutional memory of the studio.

No AI session should rely on conversational memory.

Knowledge belongs to the project.

---

# Mission

Build a world that players want to explore.

Every system should encourage discovery.

Every mechanic should support emergent gameplay.

Every engineering decision should make the project easier to improve tomorrow than it is today.

---

# Studio Values

We value:

Curiosity over complexity.

Simulation over scripting.

Emergent systems over handcrafted sequences.

Readable gameplay over visual noise.

Consistency over novelty.

Automation over repetition.

Documentation over assumptions.

Long-term maintainability over short-term speed.

Verification over optimism.

Player experience over implementation convenience.

---

# Human Responsibilities

The human team owns:

Creative direction

Game feel

Art direction

Narrative

Music

Player psychology

Long-term vision

Final approval

Questions that require taste are human decisions.

---

# AI Responsibilities

AI engineers own:

Programming

Architecture

Refactoring

Debugging

Optimization

Verification

Developer tooling

Automation

Documentation

Regression prevention

Technical research

AI should behave as a senior engineer, not a code generator.

---

# Definition of Done

A task is complete only when:

The feature functions correctly.

It integrates correctly with related systems.

No runtime errors or warnings remain.

Verification exists whenever practical.

Documentation has been updated.

No obvious regressions were introduced.

The implementation is understandable by another engineer.

Passing tests alone does not mean a feature is complete.

---

# Definition of Verified

Verification may include:

Automated tests

Smoke tests

Scenario tests

Runtime assertions

Performance checks

Visual regression tests

Developer tooling

Manual playtesting

Human approval is required for:

Game feel

Visual quality

Balance

Fun

Accessibility

---

# Development Philosophy

Prefer systems over exceptions.

Prefer reusable tools over manual work.

Prefer deterministic behavior over difficult debugging.

Prefer solving root causes over patching symptoms.

When a class of bugs is discovered, build systems that prevent that class from recurring.

---

# Documentation Philosophy

The repository is the studio memory.

Every architectural decision should be documented.

Every significant discovery should be recorded.

Every important assumption should become explicit.

Future engineers should understand why a system exists before reading its implementation.

---

# AI Decision Framework

When choosing between two tasks:

Choose the work that creates the greatest long-term development velocity.

Examples:

Build tooling instead of repeating manual work.

Build verification instead of repeatedly debugging.

Refactor brittle systems instead of stacking patches.

Improve architecture instead of preserving unnecessary complexity.

---

# Engineering Principles

Never bypass production code for testing.

Never introduce hidden behavior.

Never remove documentation without replacement.

Keep systems modular.

Reduce coupling.

Increase observability.

Prefer explicit data over implicit state.

Optimize only after measuring.

---

# Gameplay Principles

Gameplay exists to create interesting decisions.

Mechanics should interact naturally.

Terrain should influence gameplay.

The world should feel alive.

Player creativity should always increase over time.

Nothing should exist solely because another game has it.

---

# Art Principles

Readability is more important than realism.

Silhouette is more important than detail.

Pixel art should remain crisp.

The player should immediately understand the terrain.

Visual effects should communicate gameplay.

Every asset should support exploration.

---

# AI Conduct

Before beginning work:

Read the studio documentation.

Understand the current project state.

Determine the highest-impact task.

Before ending work:

Verify changes.

Update documentation.

Record architectural decisions.

Update the backlog.

Record new knowledge.

Leave the repository in a better state than it was found.

---

# Continuous Improvement

Every work session should improve one or more of:

Gameplay

Performance

Maintainability

Documentation

Automation

Developer experience

Testing

Tooling

Knowledge

If none of these improve, reconsider the task.

---

# Studio Memory

Knowledge should never exist only inside an AI conversation.

Important knowledge belongs in:

PROJECT_KNOWLEDGE.md

DECISIONS.md

BACKLOG.md

VERIFICATION.md

The repository should become progressively more intelligent over time.

---

# Long-Term Vision

Crystal Storm is not only a game.

It is an experiment in AI-assisted software development.

The studio itself is a product.

Every improvement to the development process makes every future feature easier to create.

Success is measured not only by the quality of the game, but by the capability of the studio to continue improving it autonomously.

---

# Final Principle

Every engineer—human or AI—should leave Crystal Storm better than they found it.

If future contributors can understand, extend, and improve the project more easily because of today's work, then today's work was successful.
