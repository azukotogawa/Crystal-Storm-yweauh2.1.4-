# Crystalstorm - Godot 4 Project Rules

> **Before every task, read `studio/VISION.md`** (the Crystal Storm master vision).

## Godot 4 / GDScript Coding Rules
- You are writing code exclusively for Godot 4.
- Always use the new Godot 4 signal syntax: `button.pressed.connect(_on_button_pressed)` instead of the old `.connect("pressed", self, "_on_button_pressed")`.
- Use `CharacterBody3D` (or `CharacterBody2D` for legacy 2D) instead of `KinematicBody`. Use `move_and_slide()` without passing linear velocity vectors as parameters when using the built-in physics body.
- Use `@onready` instead of `onready`.
- Use `@export` instead of `export`.

## Project Overview
**Crystalstorm** is a maze-builder tower-defense hybrid. The player constructs elaborate terrain mazes (build walls, dig tunnels) to maximize time before a growing crystal entity overwhelms the map. The crystal absorbs plants, animals, and ruins to gain power and spawn enemies. The player must balance maze-building/exploration with direct combat using weapons/relics. Win by killing the Origin Warden (immediate victory) or by destroying every crystal spawn point. The origin heart stays sealed while any minor spawn remains and while the warden lives.

Core gameplay pillars:
- Long "Maze phase" (strategy, building, routing).
- Short "Combat phase" (action).
- Topographical freedom, verticality via digging, time pressure from crystal growth.

## Current Architecture & State (2026-07)
- Full 3D voxel engine (2D prototype archived under `archive/legacy/`).
- Chunked infinite world:
  - `ChunkData.SIZE = 16`, `HEIGHT = 160`.
  - Threaded generation in `ChunkManager` (worker thread + semaphore/mutex).
  - Greedy meshing per face direction (top, bottom, sides) producing quads for `MultiMeshInstance3D`.
  - Custom spatial shader (`shaders/ChunkView.gdshader`) + texture atlas (7x10 grid) for voxel texturing + simple face-based shading.
- **World state authority:** `world/world_state.gd` (`WorldState`) owns all persistent mutable overlays (terrain height/build, feature cells/tile overrides/towns/spawns, channels) with monotonic domain revisions, batch transactions, change signals, session replace/reset, snapshot export/import (rollback), and save overlay apply/export. `TerrainEdits` / `FeatureRegistry` / `ChannelRegistry` are compatibility façades that delegate to the active session — do not reintroduce process-global static overlay maps. Worker mesh jobs freeze mesh-input overlays via `ChunkData.capture_worker_snapshot()` (stamped with `mesh_input_revision`); `ChunkManager.is_mesh_job_stale` rejects superseded tokens or mesh stamps.
- **Chunk pipeline stages:** `chunks/chunk_pipeline.gd` defines stream_request → snapshot → column → mesh → buffer → apply. Worker entry is `ChunkPipeline.run_worker_job` (stateless w.r.t. manager scratch): greedy visit grids are job-local (`alloc_greedy_visited`); micro skip lives on the job's `ChunkData._mesh_job_micro_skip`. `ChunkManager` remains the lifecycle façade (tokens, streaming, upload).
- **Deferred world bake:** Cold/invalid index primes the start stream ring + origin 3×3 via `WorldBakeService._bake_one_chunk`. `INITIAL_STREAM_READY` waits until `ChunkManager.is_start_region_ready()` (player stream ring resident + start packages). Loading UI shows live `start_region_status()` occupancy, not a canned percent. `GameplayInput.world_loading` blocks actions until the overlay dismisses. Remaining packages fill on a bounded `WorkerThreadPool` queue (`WorldBakeWorkerJob`; stream > nearby > fill). Main thread only schedules, collects, registers packages, and commits `world.index` when every expected `.chk` exists. `valid` only then. Far travel waits one on-demand worker job (same package bytes). Fill never calls `WorldState.replace_active` or mutates live overlays. Rollback: `CRYSTALSTORM_BAKE_DEFER_FILL=0` awaits the full bake before stream. `CRYSTALSTORM_BAKE_FILL_SYNC=1` restores main-thread 1/frame fill.
- **Macro / micro terrain:** Generation + column maps use dense `MacroLayerGrid` (surface/tile/flags). Dig/build/cliffs allocate sparse `MicroLayerGrid` bricks; mesh stage skips micro columns in greedy then emits via `MicroTerrainMeshCompositor` (render hides distinction). Micro is **not** persisted — save stores `height_delta`/`build_tile` only; `derive_micro_from_terrain_edits` on generate/rebuild restores bricks. Env: `CRYSTALSTORM_MACRO_TERRAIN`, `CRYSTALSTORM_MICRO_TERRAIN` (default on). `ChunkData.USE_MICRO_BRICKS` (default true) is the master switch: false skips brick writes on dig/build. The chunk mesh pipeline then calls `ChunkManager._build_macro_mesh` / `_build_macro_mesh_region` and does not enter `MicroTerrainMeshCompositor`, so those edits stay whole blocks on the greedy mesh. With the switch false, `SaveSchema.validate_and_migrate` snaps `height_delta` to whole layers (a fraction rounds away from zero) and drops `micro_bricks` / `micro_grid` / `micro_brick` / `bricks`, folding a dig into `height_delta` and a build into `build_tile`.
- **Water:** `VoxelFluidService` is edit-driven: sleep when `_dirty_cells` is empty; never scan `all_fluid_positions` on the tick path. `mark_region_dirty` / `recompute_region_now` (dig/channel) gather only the dirty box + neighbors. River *tiles* stay visual; inject 0.95 only on cells that already have a player channel. Walking does not wake the sim. `get_sim_diagnostics().phase_us` splits gather/copy/sim/persist/visual. Crystal conductivity still reads `ChannelRegistry`. One water renderer: the flood body plus chunk-mesher lids. Do not add `ChannelWaterVisual` or any second water mesh.
- **Building:** `BuildingRegistry` builtins: `stone_wall`/`wood_wall` (WorldObjects: block movement, do not raise the heightfield), `gate` (passage, no height, crystal baffle), `bridge` (WorldObject over digs, no height raise). Place via `TerrainEditor.try_build*` — delay `get_build_delay()` ~0.03s. Demolish via `TerrainEditor.try_remove` (clears a WorldObject wall, or one stacked layer; refunds 1 material; refuses towns/ruins). Input: **LMB subtract** (pick digs or removes; materials remove), **RMB place** (wall / Shift gate / Ctrl bridge). WASD move, Space jump, Q/E yaw, Page Up/Page Down pitch, V unstuck. Feedback: `structure_built` → highlight pulse + place flash. Authored meshes instance `scenes/world_object.tscn` (`WorldObject`) — gameplay cell + stored `yaw` + `visual_id` → mesh + debug Area3D. Visual identity is `visual_id`/`build_id`/flags only (never infer wall/bridge from DIRT tile). Voxels stay MultiMesh.
- **Ramps:** One landing column. Wedge mesh AABB = one voxel; approach keeps its greedy top. Collision `walkable_height_from_entry` slopes only the landing. Corner/concave transforms are right-handed yaw (no negative-scale basis). Incremental remesh halo is 1 cell (`REBUILD_EDGE_BAND`/`MESH_MARGIN`).
- **Representation contract:** `helpers/world_visual_coords.gd` is column↔world (XZ = column × voxel_scale). Face codes: 0 top, 3–6 sides (Y-greedy is top only). Incremental remesh **clips** greedy slabs outside `patch_rect` (do not drop whole merged quads). Structure yaw lives on FeatureRegistry. Audit: `LIVE_WORLD_ARCHITECTURE_AUDIT.md`. Live validation: `LIVE_GAMEPLAY_VALIDATION.md`.
- **Dev keys:** F3 compact debug overlay, F4 Live World Inspector (discrepancy flags), F6 texture blueprint (Settings checkbox, off by default; placeholders restore on toggle), F11 bug report, ESC pause (Resume / Settings / World Select / Quit). Terrain collision stays `VoxelFloorProbe`; `WorldObject` Area3D is debug-only.
- **Cheap terrain lighting:** terrain does not cast shadow maps. `shaders/terrain_shade.gdshaderinc` shades from the face normal and a sun uniform, with edge darkening, voxel noise, crystal-cell glow, and cave fog. The directional light rays follow the terrain sun `(0.55, 0.82, 0.38)`, so the shadow falls on the ground. The ortho camera far is 520 because Godot sizes those shadows from the camera far plane. Gameplay terrain (`ChunkSurfaceMesh`, plus the chunk and ramp fallbacks) calls `cs_depth` so vertex-color corner AO and a per-cell corner darken are visible, then `light()` multiplies only the directional shadow attenuation (no Lambert). Tunables `terrain_corner_darken`, `terrain_shadow_darken`, and `ssao_radius` live on the quality config. Top and side corner AO is vertex color alpha (`helpers/terrain_vertex_ao.gd`, off on LOW and SAFE); ramp vertex alpha stays 1. Contact blobs are one quad each (`helpers/contact_shadow.gd`) and do not cast shadow maps. LOW and SAFE zero `terrain_ao_strength`, the corner darken, and the shadow darken, and hide blobs.
- **Voxel models:** `docs/voxel-format.md` (`crystalstorm-voxel-v1`). Authored files live in `assets/voxel/` (shared palette, `vegetation/tree_oak.json`, `tree_birch.json`, `tree_pine.json`, and `entities/player.json` plus three crystal mites). The player rig and the mite rig load those parts (one mesh each) and keep the existing bone pivots. `CrystalVoxelLoader` greedy-meshes one `ArrayMesh` with vertex colours, plus one mesh per named part, and caches them under `user://crystal_voxel_cache/`. `.vox` is an optional MagicaVoxel import (Z-up to Y-up), not the store. Gameplay vegetation instances the thinned LOD meshes from `assets/voxel/vegetation/lod/` (`VegetationVoxelCatalog`) as one MultiMesh per chunk. Near trees (10 columns) use LOD0, at most 5000 quads; farther trees use the 8-per-block shell. The full reference JSON files stay the loader check and are not spawned.
- **Texture set:** Settings > Graphics chooses Original or Batch 1 (`PlayerSettings.texture_set`, default Original). `helpers/texture_set.gd` maps `res://assets/art/X` to `res://assets/art_batch1/X` when Batch 1 is selected and that file exists. Item, vegetation, and mob loads go through it. F6 blueprint still replaces whichever set is active. Regenerate with `tools/gen_texture_batch.gd`. See `docs/TEXTURE_BATCH1.md`.
- **Terrain loop (complete):** Cursor = live mouse cell (no hysteresis). Dig/build **only** that cell (`get_action_column`); out-of-range fails with toast (no facing dig). Edits flush mesh + immediate water reflow; `terrain_edited` invalidates crystal height caches. Macro/micro dirty path on dig. Soft-follow movement; world borders stop player/crystal. Visual: dig dust + build flash + highlight pulse.
- **World borders:** `helpers/world_border.gd` — playable half 1024; ±X ocean, ±Z mountain (not rotated per seed; the notebook keeps those sides). A seeded rim about 28–44 columns wide shapes the coast and the range. Perimeter cells are ocean, or mountain at least `MOUNTAIN_EDGE_MIN` (36) with a 16-unit headwall, so the edge is water or a cliff. The crystal corner (inset 72) stays inland of that rim. Beyond the box, ocean stays at or below the rim sea and the range stays at or above the crest. Player: `blocks_player_at` (ocean tiles always; border mountain tiles + early transition bands). Crystal: `allows_crystal` / `is_playable` in sim active mask. Map: rim styling in `TopographicalMapBuilder._apply_border_map_style`.
- **Save architecture (schema v2):** `systems/save_schema.gd` + transactional `SaveGameService`. WorldState is the sole overlay persistence authority (`export_persistence_bundle` / `import_persistence_bundle` with revisions). Per-world file `user://saves/world_{id}.json` (`save_world_id` / `load_world_id`); `WorldManager.active_world_id` + `pending_resume` so catalog Play restores after `INITIAL_STREAM_READY`. Leave World saves first, then clears ids. Slot files remain for F5/F9. Load: validate/migrate → checkpoint → pause stream/sim → apply WorldState → runtime → single rebuild → resume; failure rolls back checkpoint. Do not re-scatter overlay serialization into static registries. Micro bricks are never in the payload. Crystal mite unlock is `AbsorptionUnlockDef.unlock_at_start` on the GameConfig table (no CrystalManager special-case).
- **Composition root:** `systems/composition_root.gd` + `service_registry.gd` + `runtime_config_resolver.gd` own production boot stages (CONFIGURED → … → RUNNING), typed service registration, and EffectiveRuntimePolicy precedence (defaults → project → quality → platform → debug). `ProgressionService` (`systems/progression_service.gd`, `XP_ENABLED` default true) is registered as `progression_service` and owns run XP, level, and skill points (`50 * level^1.5`). `SkillService` (`systems/skill_service.gd`, `SKILLS_ENABLED` default true) is registered as `skill_service` and spends those points to unlock catalog skills, then equips up to 3 actives on `skill_1`/`skill_2`/`skill_3` (C/H/J) with cooldowns. Ability effects are not in this service. Dash (`player/dash_skill.gd`) is the first: the player listens for `skill_activated`, slides `DashSkill.DISTANCE` columns through the walk probe, and ignores damage for `DashSkill.INVULN` seconds. The catalog cooldown for dash is `DashSkill.COOLDOWN`. Ground slam (`player/ground_slam_skill.gd`) is the miner active: it breaks the 3×3 surface under the player through one `TerrainEdits.dig_cells` batch and damages crystal enemies and world entities standing on that patch for `GroundSlamSkill.DAMAGE`. Its catalog cooldown stays `SkillService.DEFAULT_COOLDOWN` until Q-046 is answered. Crystal Pulse (`player/crystal_pulse_skill.gd`) is the next fighter active: it deals `CrystalPulseSkill.DAMAGE` to crystal enemies inside `CrystalPulseSkill.RADIUS` columns and multiplies crystal flow on any edge touching that disk by `CrystalPulseSkill.SLOW` for `CrystalPulseSkill.DURATION` seconds of simulation time. The clock pauses with `GameplayInput`. The catalog cooldown is `CrystalPulseSkill.COOLDOWN`. `CrystalFluidSim` reads the scale in conductivity and frontier birth; `CrystalSimulation.tick` advances it when a tick finishes. Quick Wall (`player/quick_wall_skill.gd`) is the builder active: it places the `wall_segment` blueprint one column in front of the player, turned across that facing, through `TerrainEditor.try_place_blueprint` at `QuickWallSkill.COST_SCALE` of the material cost, and it does not wait on the build delay. A crafted piece stays in the bag. The catalog cooldown stays `SkillService.DEFAULT_COOLDOWN` until Q-046 is answered. A failed place clears that cooldown. Passives live in `player/skill_passives.gd`: `miner_passive` adds `MINING_SPEED` dig speed, `fighter_passive` adds `MAX_HP` max health, and `builder_passive` adds `STRUCTURE_HP` hit points per cell on structures placed after the unlock. `ui/skill_tree_panel.gd` opens on K (`skill_tree`) with the fighter, miner, and builder branches and spends the same skill points. While it is open, `ui_up` / `ui_down` / `ui_left` / `ui_right` move the highlight and `ui_accept` spends a point on that skill. The run save stores progression and the skill block (`skills`); there is no meta-progression file (D-158). `GameManager` grants that XP from kill tier, crystal hits, blocks mined, structures placed, and ruin or POI discovery; the amounts are the `XP_*` constants on the service. Critical handoffs use `ConfigService.apply_to_registered` / `PerformanceService.apply_to_registered` (policy folded into effective quality via `fold_policy_into_quality`); groups remain UI/debug adapters only. Quality must not mutate authored `WorldGenConfig` authority fields. Diagnostics: `CompositionRoot.get_diagnostics()` / `get_health_report()`.
- **Spatial Query Layer:** `systems/spatial_query_layer.gd` + `spatial_query_service.gd` own runtime spatial **discovery** (grid + chunk indices; radius/AABB/nearest/ray/region/neighborhood). Combat/targeting obtain candidates through the layer; no gameplay logic inside the layer. Chunk load/unload and entity move update indices incrementally; save restore calls `rebuild_from_runtime()`.
- **Crystal simulation split:** `CrystalManager` is the gameplay façade. `CrystalSimulation` (pure, no scene tree) consumes `CrystalSimSnapshot` and emits typed events; `CrystalPresentation` schedules mesh rebuilds from those events. Do not re-merge fluid/mesh logic into the façade or add `get_tree()` inside `CrystalSimulation`.
- World gen: `world/InfiniteNoiseWorld.gd` using FastNoiseLite (height/precip + dedicated river_path for networks) → exactly 5 real-life biomes (plains, steppe, forest, marsh, mountain) with topo/rugged + river moisture bias; realistic rivers that carve depth (incised channels at lowered surface_y using RIVER + depth variants) so they traverse biomes following valleys (see helpers/voxel_types.gd). The river mask is the unshifted `_river_noise` ribbon. Inside `SPAWN_RIVER_CLEARANCE` (96 columns) around the crystal-heart corner (`WorldBorder.origin_corner_for_seed`, same cell as `CrystalManager.origin_corner_for_seed`) the mask is inactive and river tiles are suppressed so spawn is not a river; on and beyond the rim the mask matches the unshifted formula. The world origin is not cleared. Height carving is unchanged.
- Player movement: Custom voxel-aware collision + gravity (not yet relying on CharacterBody3D physics body features in the script). Feet stand on the rendered slab top (`surface + layer`), not inside that voxel. If the capsule overlaps solid terrain, the probe pushes the body to the nearest free stand (every few physics frames, plus V). Orthographic Camera3D: continuous Q/E yaw, Page Up/Page Down and middle-mouse pitch (clamped, default iso offset unchanged), mouse-wheel zoom.
- Scenes: `scenes/frontend.tscn` is the player-facing entry (MAIN MENU → WORLD SELECT → NEW WORLD / SETTINGS). Play loads `scenes/main.tscn` (Node3D root "Game", script `main.gd`) and is playable at `INITIAL_STREAM_READY`. Leave World returns to WORLD SELECT. Catalog: `systems/world_manager.gd` (no UI `.chk` IO). Dev biome viewer: `scenes/world_viewer.tscn`. Legacy scenes live in `archive/legacy/`.
- Boot chain: `ConfigService` → `PerformanceService` → `GameVisualRegistry` → `WorldFeatures` (feature seed) → `VoxelWorld` creates `ChunkManager` → `on_chunk_manager_ready` binds TerrainEditor/EntityManager/config → `CrystalManager` sim → `WorldVisuals` refresh on `visuals_ready`.

## Development Guidelines
- Prefer the 3D voxel system in `chunks/` + `player/` for all new gameplay features (maze building, digging, crystal simulation, combat).
- When editing terrain interaction, go through `ChunkData` + `ChunkManager` APIs (get/set voxels, rebuilds, collision queries). Mutate persistent overlays via `TerrainEdits`/`FeatureRegistry`/`ChannelRegistry` façades or `WorldState` directly — never add new static overlay storage.
- Keep the world deterministic given a seed. Overlay restore uses `WorldState.restore_overlay_snapshot` / save apply for identical seed+payload replay.
- Thread-safety: generation jobs run off-main on frozen worker snapshots; use `call_deferred` for tree modifications. Do not read live WorldState maps from workers.
- Performance: 2D heightfield (surface+tile maps only) + Y-greedy rect merge + side run-length lips; BOTTOM faces disabled; RENDER_DISTANCE default=3; throttled render drain (5/chunk max per frame); debug UI rate-limited. Be mindful of total MultiMesh instances and streaming distance. Tune RENDER_DISTANCE in inspector for FPS vs horizon (higher = more draw).
- **Difficulty telemetry:** autoload `DifficultyTelemetry` (`systems/difficulty_telemetry.gd`). Session of player deaths, damage taken, and damage dealt by source, plus time-to-kill per enemy type (first hit until death) and XP rate (XP per minute, level-up times). Each row is stamped with the session id and timestamps. It listens for `damage_taken`, player `died`, `combat_damaged`, `killed`, world-entity `died`, and progression `xp_gained` / `level_up`. Each session is written to `user://telemetry/<session_id>.json`. When `CRYSTALSTORM_EVIDENCE` or `CRYSTALSTORM_RUN_ID` is set (cs-verify), that file is also copied to `<run>/telemetry/<session_id>.json`.
- **Runtime profiler (permanent):** autoload `PerfProfiler` (`systems/perf_profiler.gd`). Hierarchical frame report (chunks/streaming/crystal/entities/world/render/ui/memory/workers + HOTTEST). Instrument with `begin`/`end`/`record_us`/`set_gauge` only — no gameplay changes. Debug panel `--- PERF ---` block; headless `scripts/profile_gameplay.gd`. See `PERFORMANCE_RUNTIME.md`. Budget target 16.6 ms/frame.
- **Frame budget scheduler (Phase 3):** autoload `FrameBudgetScheduler` — per-system unit + soft wall budgets, FIFO queues, min-units starvation prevention. Crystal event dispatch, living-world ruin scan, town defense ticks, and chunk apply drain through it. Critical crystal events still immediate; save export flushes dispatch. See `PERFORMANCE_PHASE3_REPORT.md`.
- **Juice / audio hooks:** autoload `AudioManager` (`systems/audio_manager.gd`) with Master/Music/SFX/UI buses. Ids live in `config/audio_manifest.gd`. Missing files are skipped. Particles and swing arcs are pooled in `VfxPool`. Hit-stop, shake, flash, and walk bob are `Juice`, gated by `PlayerSettings` (`screen_shake_enabled`, `hit_stop_enabled`, `flash_effects_enabled`, `reduce_motion`, bus volumes). Action and milestone timings live in one resource, `config/default_game_feel.tres` (`GameFeelConfig`, D-233). Autoload `GameFeel` reads it. `play_action` and `play_beat` request hit-stop, shake, and flash and emit `sound_hook`. They set `Engine.time_scale` for everyone, never pause the tree, and keep slow-mo at or above 0.35. Headless skips the dip. Toasts use `banner_seconds()` (2.5 s). Level-up, skill unlock, treasure, relic, landmark, crystal damage stages, boss spawn, and the win call `play_beat` and hold that beat's own banner. The toast sits at y=200, under the crystal HP panel and the showcase chapter label, and it ignores the mouse. A later beat replaces a slow-mo this hook already owns; it still never pauses the tree, never stacks on hit-stop, and never drops below 0.35. Dash, ground slam, crystal pulse, quick wall, sword swing, bow shot, multi-block break, and building placement wait out that telegraph, then play the hit, linger, and recovery. A shared gate keeps two different actions from resolving within 150 ms. Crystal mite bites, warden slams, charges, bursts, and bites, and the crystal burn pool wait out `GameFeel.enemy_telegraph` before damage, and the player can still move. Held-item poses, the aim marker, hit/miss/blocked markers, and mining cracks are `ItemAnim`, `HeldItemView`, `AimIndicator`, `HitMarkers`, and `BlockBreakFx` (`hit_markers_enabled` and `crack_overlay_enabled`, default on). Menus, keybinds, UI scale, the colour-blind palette, the tutorial, and the run summary are in `studio/wiki/UI.md`. See also `studio/wiki/Effects.md`. Do not add audio files until they are real recordings.
- Input: Current actions use built-in "ui_*" + custom "jump", "rotate_left", "rotate_right" (see `project.godot`).
- Testing the game: `godot scenes/main.tscn` or `godot .` (main scene set in project.godot). Headless CI: `godot --headless -s scripts/run_all_verify.gd` (full suite via `scripts/run_all_verify.sh`; includes `verify_world_state` + `verify_world_state_stale_worker`). Named verify steps call `await ProbeCapture.capture_step(step_name)` (`helpers/probe_capture.gd`). Headless and any run with no root viewport return an empty path and do not grab a texture. A windowed run writes `<index>_<step_name>.png` under the `CRYSTALSTORM_EVIDENCE` folder's `steps/` (else `CRYSTALSTORM_RUN_ID` under `D:/ARCHIVE/CrystalStorm/verify-evidence`). The slugs live in `.cursor/skills/verify-crystal-storm/SKILL.md`.
- Perf presets: env `CRYSTALSTORM_PERF_PRESET=low|medium|high|safe` or `CRYSTALSTORM_SAFE_MODE=1`.
